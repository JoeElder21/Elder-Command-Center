# QA/QC Checklists

Run these before any deliverable is called complete.

## Completeness Checklist

Before any deliverable is considered complete:

- [ ] All sections required by the deliverable template are present
- [ ] No placeholder text remains (e.g., "[TBD]", "[INSERT]", "XXX")
- [ ] All referenced attachments or exhibits are identified
- [ ] Assumptions section is complete
- [ ] Risk flags section is complete
- [ ] Next steps are specific, assigned, and dated
- [ ] Document is self-contained — reader does not need to ask clarifying questions

## Technical Accuracy Checklist

- [ ] All dimensions and elevations are internally consistent
- [ ] Code references cite the correct section and edition
- [ ] Calculations use correct formulas and units
- [ ] Design values are within acceptable ranges
- [ ] Material specifications match the application
- [ ] Jurisdictional requirements are project-specific (not generic)
- [ ] Coordinate system and datum are identified where applicable

## Audience Calibration Checklist

- [ ] Technical depth matches the intended audience
- [ ] Jargon is appropriate for the reader (client vs. contractor vs. agency)
- [ ] Recommendations are actionable by the intended recipient
- [ ] Financial information is at the right level of detail
- [ ] Visual aids (tables, diagrams) support comprehension

## Formatting Checklist

- [ ] Consistent heading hierarchy (no skipped levels)
- [ ] Tables are properly formatted with headers
- [ ] Lists are parallel in structure
- [ ] Numbers use consistent formatting (commas, decimal places)
- [ ] Dates are in consistent format (Month Day, Year preferred)
- [ ] Page/section breaks are logical
- [ ] JEDS brand applied to client-facing documents

## Existing / Demo / Proposed Checklist

- [ ] Every infrastructure element is labeled as Existing, Demo, or Proposed
- [ ] Existing conditions match survey data
- [ ] Demolition items are clearly identified and quantified
- [ ] Proposed elements include all necessary specifications
- [ ] No ambiguous references that could be misinterpreted in the field
